# SPATIAL GROUND TRUTH PROTOCOL

## 1. Purpose
To objectively measure the accuracy of the deterministic spatial reasoning engine without conflating it with YOLO detection errors, and without fabricating spatial relationships from the ChemEq25 detection dataset.

## 2. Independence Principle
Ground truth must be independently authored by humans (or systematically synthesized under controlled geometries). It CANNOT be generated by running the spatial rule engine and saving its outputs as "correct". An independent oracle ensures that mathematical defects in the engine are actually caught.

## 3. Protocol Definitions
- **Bounding Boxes**: Boxes must be strictly within [0,1], normalized to image dimensions, with the origin (0,0) at the top-left corner.
- **Expected Counts**: Integer values representing the true required equipment presence for the specific image layout.
- **Regions**: Specifically delineated bounding box areas mapping to logical benchtop zones.
- **Compliance Status**: A strict boolean True/False defined independently of engine output.
- **Violations**: A specific list of violation types (MISSING_OBJECT, EXTRA_OBJECT, MISPLACED_OBJECT, SPATIAL_RELATION_VIOLATION) that correspond strictly to the setup rules for that image.

## 4. Synthetic vs Real Data
Currently, only **SYNTHETIC SPATIAL EVALUATION DATA** is used. These synthetic fixtures map perfectly overlapping or strictly separated boxes to rigorously test mathematical relationships (e.g., left_of, inside).

When extending to real photographs:
1. Annotators must manually draw regions.
2. Annotators must manually draw object boxes.
3. Annotators must manually determine if the setup is compliant according to the written protocol, regardless of how the bounding boxes happen to align computationally.
