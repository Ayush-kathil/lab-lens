# Report Figure Checklist

When preparing the final PDF rendering of the academic report, the following screenshots, diagrams, and visual artifacts must be manually captured or generated and inserted into the document.

### Required Figures:

- [ ] **Figure 1: System Architecture**
  - **Source:** Mermaid diagram rendered from Section 8.
  - **Action:** Use a Markdown renderer (like GitHub or a Mermaid live editor) to capture the exact high-level architecture diagram showing the separation of YOLO and the Rule Engine.

- [ ] **Figure 2: System Workflow**
  - **Source:** Mermaid sequence diagram rendered from Section 9.
  - **Action:** Render and capture the sequence diagram demonstrating the data flow from User $\rightarrow$ Quality Gate $\rightarrow$ ML $\rightarrow$ Spatial Engine $\rightarrow$ Compliance.

- [ ] **Figure 3: Dataset Preparation Pipeline**
  - **Source:** Terminal output / Audit scripts.
  - **Action:** Take a screenshot of the `audit_dataset.py` terminal output demonstrating the deduplication logic, specifically the logs showing exact duplicates found and cross-split leakage blocked.

- [ ] **Figure 4: Example Detection Result**
  - **Source:** `outputs/` folder (generated by LabLensPipeline or YOLO directly).
  - **Action:** Provide a clear cropped image of a successful laboratory benchtop detection (e.g., from the validation set) showing YOLO bounding boxes and confidence scores.

- [ ] **Figure 5: Spatial Relation Illustration**
  - **Source:** Diagrammatic representation.
  - **Action:** Create or capture a simple vector diagram illustrating how the `BoundingBox` geometry determines `above/below` or `inside_region` using centroid coordinates.

- [ ] **Figure 6: Compliance Result Example**
  - **Source:** CLI output.
  - **Action:** Run the pipeline in human-readable mode (e.g., `uv run python pipeline.py ...`) and screenshot the colored terminal output showing `COMPLIANT` or `NON_COMPLIANT` with the breakdown of spatial conditions.

- [ ] **Figure 7: Robustness / Error Flow**
  - **Source:** CLI output.
  - **Action:** Run the pipeline on a corrupted image or invalid JSON setup configuration to screenshot the system safely failing with an `ERROR` state rather than a silent crash.

- [ ] **Figure 8: Dataset Audit / Duplicate Analysis**
  - **Source:** `docs/EXTERNAL_DATASET_FINAL_REPORT.md` or CSV files.
  - **Action:** Screenshot the markdown table or CSV viewer showing the exact counts (e.g., 0 Exact Duplicates, 10 Candidates) to visually back up the dataset engineering claims.

- [ ] **Figure 9: External Benchmark Workflow**
  - **Source:** Annotation CLI interface.
  - **Action:** Run `uv run python scripts/annotate_external_cli.py` and capture a screenshot of the OpenCV window and terminal prompt, proving the manual `selectROI` methodology independent of ML predictions.

- [ ] **Figure 10: Test / Evaluation Summary**
  - **Source:** Terminal output.
  - **Action:** Run `uv run pytest -q` and screenshot the final green `100 passed` output string to prove the software engineering integrity of the pipeline.

**Important Note:** Do not fabricate or synthetically alter any screenshots. If an artifact does not exist (e.g., a fully annotated external benchmark image), leave the corresponding figure as a clear placeholder stating `[Image Pending Human Annotation]`.
